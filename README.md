# DCE · Divergence-Consensus Engine

**Scaffold 结构空间上的多视图差分层。**

给定多个已经结构化、位于同一知识空间中的认知视图，识别它们的共同结构、
明确冲突、表达缺失与结构细化，并生成一个**可追溯的派生结构**。

DCE **不负责发现知识、不负责判断真伪、不负责决定哪一个模型正确。**
它负责回答：**这些视图在哪里相同？在哪里不同？差异究竟属于什么类型？**

> **Consensus ≠ Truth** · **Divergence ≠ Error**
> DCE 的输出全部属于 `derived structure`，不是 `ground truth`。

---

## 它在链上的位置

```text
Scaffold          知识空间长什么样
   ↓
Arena             不同主体在这个空间里说了什么、哪里发生分歧
   ↓
Structured Views
   ↓
DCE               多个结构化视图之间，在结构层面究竟有什么共同与不同   ← 本仓库
   ↓
Derived Structure
   ↓
（未来的认知层：情境激活 / 几何表示 / 动态构造 —— 不在本仓库）
```

### 它不是什么

知识库 · 向量数据库 · 搜索引擎 · RAG · 模型评测器 · 投票系统 · Truth Engine ·
自动裁判 · 自动合并知识 · 自动修改底层事实 · 新的 ontology。

**也不是**曲率、神经场、长期记忆或动态构造 —— 那些在设计稿里是**更后面的层**，
本仓库一个都不做（这条有可执行检查：`python -m checks.scope`）。

## 快速上手

零依赖、纯标准库、纯内存，只要 Python（开发时用 3.14，代码兼容 3.9+）。

```bash
python -m checks               # 全部检查与四组测试（23 条断言）
python -m checks identity      # 只跑某一组
python tests/run_tests.py      # 同一个测试集，另一个入口（本机没有 pytest）
```

```python
from core import view as V
from analysis import synthesis as S

a = V.make_view(view_id="A", source_ref="paper://x", source_kind="paper",
                nodes=["con-0001", "judge-0001"],
                edges=[("con-0001", "judge-0001", "supports")])
b = V.make_view(view_id="B", source_ref="model://y", source_kind="model",
                nodes=["con-0001", "judge-0001"],
                edges=[("con-0001", "judge-0001", "contradicts")])

syn = S.build([a, b])
S.verify_synthesis(syn, [a, b])       # 逐条与源视图对账
```

## 结论

### §十五 四组测试

| 测试 | 判据 | 结果 |
|---|---|---|
| **Test 1 Identity** | A=B=C → 100% 共识、0 分歧 | **过**：共识 = 全部单元，四类分歧全为 0 |
| **Test 2 Orthogonal** | A∩B=∅ → 0 共识、大量缺失，**不能全叫矛盾** | **过**：共识 0、缺失 2、**矛盾 0** |
| **Test 3 Controlled Divergence** | 植入 10 矛盾 / 20 缺失 / 10 精炼 / 5 竞争解释，**分别**恢复 | **过**（在无歧义构造下）：五类召回 1.000，类型串 0。⚠️ **这条的适用范围比它看起来窄，见下** |
| **Test 4 Interference** | `hash(A_before) == hash(A_after)` | **过**，另加三条更严的（见下） |

Test 4 额外验的三条（只比哈希不够）：

1. 每个视图**逐字段深层相等**（哈希相同但字段被重排过，不算通过）
2. 合成结果里记的视图指纹 = 当场重算的指纹
3. **后加入一个视图**，先前那些视图的指纹不变（增量写入不污染历史）

Test 3 的额外一条：**报出来的每条主语都逐条过定义校验，定义不符 0 条。**
这一条比「多报数」重要 —— 一条私有边**按定义就是 omission**，
拿它当 precision 的分子会把「定义如此」和「算法错了」抹平成同一个数字。

### ⚠️ Test 3 的适用范围：只在无歧义构造下「分别恢复」是良定义的

Test 3 的判据是「DCE 必须能够**分别**恢复它们」。**这句话只有在预埋项两两无歧义时
才有定义**，而那需要一个特定构造：四类各占各自专用的、互不重叠的视图。

本仓库上一轮的语料生成器正好是那么造的 —— 它**拒绝**任何种不干净的配置
（144 个配置里只有 54 个建得出来），于是 54/54 都是干净情形。**召回 1.000 是真的，
但它是一个被选出来的测试床上的真。**

改成**允许交叠**（`allow_overlap`，默认开）之后，`checks/corpus.py` 在
**720 个配置 / 595 个可建**上扫了一遍，召回必须分三档报：

| | strict（类型报对） | accounted（或按定义该算另一类且已记录） | **真漏** |
|---|---|---|---|
| contradiction | 355/355 | 355/355 | **0** |
| omission | 320/355 | **355/355** | **0** |
| refinement | 75/115 | **115/115** | **0** |
| alternative | **15/115** | **115/115** | **0** |

**算法一次都没漏（真漏 0 条）。**交叠下变的是「这条预埋按定义该算哪一类」，
而这件事被逐条记录在案、可核验。所以正确的说法不是「DCE 在交叠下变差了」，
而是 **四类不是彼此独立的标签，而是一个边界随构造移动的划分**。

### 反例扫描：六条结论在 595 个配置上处处成立

每条「必须处处成立」的结论都拿到整片网格上撞了一遍，**零反例**：

| 命题 | 结果 |
|---|---|
| C1 Coverage ≡ 1 且合成里无幻影 | **595/595** |
| C2 DCE 的划分 == union+frequency 的划分 | **595/595** |
| C3 每条报出的记录满足该类的定义 | **595/595** |
| C4 产物里无评分 / 权重 / 真值键 | **595/595** |
| C5 合成不污染源视图（含逐字段） | **595/595** |
| C6 `focused ≥ flat` | **595/595** |

被拒的 125 个是**真约束**（core 只有 0 条边就种不出矛盾；core 只有 2 条边装不下
8 条植入），不再是构造假象 —— 可达率从上一轮的 **38% 提到 71%**。

同时焦点机制终于被真正跑起来了：**焦点数分布 1个×103、2个×141、3个×179、
4个×112、5个×54、6个×6**。上一轮的语料库只会造连通随机图，
而焦点用「共享节点」并查集（传递闭包），连通图上它**恒等于 1** ——
上一轮那个「1416 条分歧塌成 1 个焦点」就是这个原因，不是 bug，是材料的问题。

### §十六 消融（三个基线）

| | 划分是否与 DCE 相同 | 类别分辨率 | 5 类准确率 | 粗任务准确率 |
|---|---|---|---|---|
| **DCE** | — | **5 类** | **0.988** | 1.000 |
| **Baseline C** 并集+频次 | **完全相同** | 2 类 | 0.506（它只会说「共识」） | **1.000** |
| Baseline A 相似度 | — | — | 分歧/共识 **AUC 0.877** | — |
| Baseline B 相似度+聚类 | — | — | AUC 0.500（扫阈值取最好，cut=0.1） | — |

**这张表要说的是三句话，缺一句都会读错：**

1. **DCE 的划分与 union+frequency 完全相同。** 两者在定义上就是同一个
   （出现次数 == 视图数）。**DCE 在这一层没有增量。**
   这条在 595 个配置上**零反例**。
2. **增量在类型上**：5 类 vs 2 类；5 类准确率 0.988 vs 基线的**最好可能** 0.506。
   ⚠️ DCE 那一格**不再是 1.000** —— 扩语料之前它是 1.000，
   交叠构造引入类型歧义之后掉到 0.988。**掉下来的那一部分正是真实存在的东西**
   （见上面 Test 3 的三档召回）。
3. **但粗任务上基线是 1.000 —— 和 DCE 一样准。**
   所以「DCE 比 union 更准」是错的；正确的说法是
   **「DCE 能把基线必须合并的东西分开」**，那是**表达力**增量，不是准确率增量。

⚠️ 基线 B 的 AUC 从扩语料前的 0.833 掉到了 **0.500（随机水平）**。
这不是实现退步，是**材料换了**：上一轮的语料只会造连通随机图，
相似度聚类的连通分量刚好与结构区域重合；形状多样之后这个巧合没有了。
**「相似度 + 聚类」的 0.833 本身就是那套窄语料的产物。**

⚠️ 基线 A/B 用的是**字符二元组 Dice**（rl-scaffold `tools/find_path.py` 的
`MATCH_SPEC` 就是这一条），**是「相似度的替代品」，不是 embedding** ——
§十七 要求纯标准库，而 embedding 需要一个模型。
基线 B 的「聚类」必须有一条切分阈值，而 `§T0.3` 禁止拍阈值，
所以本仓库**把它的阈值当旋钮扫描、报它最好的一档**：给基线它最强的一击。

### §十三 两个指标：Coverage 退化，Compression 才在动

在 16 个网格配置上量过：**Coverage 恒等于 1.0000**。

这不是实现问题，是**设计的推论**：分歧记录逐条罗列每一个差异，
而一个单元只有两种下场——要么在所有视图里都有（→ 共识），
要么至少缺在一个视图里（→ 某条缺失或被精炼认领）。**没有第三种。**

所以设计稿 §十三 说的「高 Coverage + 高 Compression 的区域」
**在本设计里退化成一条 Coverage = 1 的线**，真正在变的是 Compression，
而它只取决于**概括层级**：

| 口径 | 16 个配置上的范围 |
|---|---|
| `flat`（每条分歧记一条） | 1.07 – 2.03，**随视图数上升趋近 1** |
| `focused`（每个焦点算一条） | 2.00 – 5.44 |
| `synopsis`（焦点 + 类型直方图） | 1.91 – 4.57 |

`flat` 退化的原因很具体：缺失是逐 `(视图, 单元)` 罗列的，
于是合成与输入**同阶增长**。这条度量的是「有没有概括」，不是「DCE 好不好」。

## §十八 的 adapter：单向翻译，核心不许依赖它

上游（Scaffold / arena）各有自己的数据模型。`adapters/` 是它们与
`Structured View` 之间的翻译层，存在的理由是：**翻译必须发生在一个明确的地方**，
否则上游的字段会慢慢渗进 `core/`，DCE 就变成上游的一次重新实现，
而 §十九 划的那条边界会在没人注意的时候消失。

这条约束是**方向性**的，所以它需要一条专门盯方向的检查：

```
core/ analysis/ metrics/  不许 import adapters     ← checks/boundary.py 钉住
上游形状 → Structured View   允许，且只发生在 adapters/
```

方向一旦反过来，**不会让任何测试变红** —— 所以必须有一条检查专门盯着它。

### ⚠️ 设计稿 §十八 声明的六项接口，四项与实际不符

| 设计稿声明 Scaffold 提供 | 实际 |
|---|---|
| Node | **有**（11 字段，`SPEC.md:38` 明文不得增删） |
| Edge | **没有**。`relations` 是 `list[str]`，**无种类、无方向元数据** |
| Situation | **没有**。`cues` 是情境索引，但没有 Situation 实体 |
| Source | 只有字段，**没有实体**；且一篇节点只有**一个** source 槽位 |
| Cue / Evidence Status | 有（就是 `cues` / `evidence_status`） |

### ⚠️ 一条会改变结论的取舍

**从 Scaffold 出来的视图不可能产生 `contradiction`。**

矛盾的定义是「同一对端点上，两个视图给出**被声明为互斥**的两种 relation」。
Scaffold 的关系没有种类，所以它的边全部落在本仓库**声明的**占位种类
`dce_untyped` 上（不是从上游借的词 —— 上一版借了 `related_to`，
而那个词属于「规格里有、产品代码从不产生」，借它等于把本层的占位符伪装成上游的输入）。

于是同样一份差分算法，输入形状不同，**能回答的问题就不同** ——
Scaffold 视图 `can_produce = (consensus, alternative, omission, refinement)`，
arena 视图多一个 `contradiction`。这件事写在 adapter 的声明里，不留给读者去猜。

### ⚠️ 一处**真实的接口错位**（已量出，未修）

Arena 里「两方对立」长这样：

```
evid-0001 --supports----> claim-0001
evid-0002 --contradicts-> claim-0001
```

**共享的是 `to`，不同的是 `from`。** 而 DCE 的矛盾判据要求 `(from, to)` 相同、
只有 relation 互斥。于是这对在 DCE 里**一条矛盾都报不出来** ——
实测报出矛盾 **0 条**、omission 3 条。

**这是判据错位，不是实现 bug，而且我没有顺手去改 DCE 的核心定义** ——
那正是「被上游结构带着跑」。三条可能的出路都还没走：

1. 把 DCE 的 `contradiction` 从「同 `(from,to)`」放宽成「同 `to`、互斥 kind」
   —— 那是改本层核心判据，需要设计稿点头
2. 在 adapter 里 **reify**：把「对同一 claim 的两种对立态度」显式建成一个共享端点
   —— 这是 adapter 的活
3. 承认这形状在 MVP 范围外

这个数字被钉成测试（`test_arena_disagreement_gap_is_measured_not_hidden`），
所以**哪一天它变了，会当场被看见**。

## 第一次拿真实数据跑（`rl-scaffold` 的 36 个真节点）

`python -m checks realdata`。语料不在时会**显式跳过**（`ok is None`，单独计数，
并打「跳过不等于通过」）—— 一个「语料不在就静默通过」的检查，
与一条永远通过的检查，在输出上长得一样。

三条只能由真实数据做出来的事：

**一、`source.kind` 同名不同义。** Scaffold 的是节点级的**证据体裁**
（论文 26 / 教材 7 / 官方文档 2 / 其他 1，中文），DCE 的是视图级的**产出者**
（model / human / paper / …，英文）。取值域**交集为空** —— 但那不是要写翻译表，
**它们不在一个轴上**，硬翻译会把「体裁」伪装成「产出者」。
所以视图的 `source_kind` 一律是 `"scaffold"`，节点的 `source.kind` **只当切分键**。

**二、这份语料是「一个知识库的切面」，不是「多份立场」。**

```
按 source.kind 切出 4 个视图：其他1 / 官方文档2 / 教材7 / 论文26
全部视图的单元交集 = 0   →   共识必然 0 项
分歧 192 条，全部是 omission；矛盾 0 条（关系无种类，定义上不可能）
```

切面之间的关系天然就是「谁缺了什么」，于是 omission 定义性地压倒一切 ——
**192 条里没有一条是新信息。** 这是语料的形状问题，不是 DCE 的问题：
36 个节点的 `filled_by` **全部是同一个模型**，那是一个主题、一个填充者的一份结构，
而设计稿 §七 说的视图是「模型 / 专家 / 论文的一个立场」。

**真要多视图，需要同一主题上的多份语料，或者走 arena 那条路（它记录「谁说了什么」）。**

**三、`flat` 口径在真实规模上不可用。**

```
输入 64 个单元  →  flat 压缩比 0.33（合成比输入大 3 倍）
                   focused 7.11、synopsis 6.40（9 个焦点）
```

上一轮只能说 flat「会先在这里出问题」，真实数据把它坐实了：
**逐条罗列差异的合成，比摊开原始视图还大。** 让它收得回来的是 §十一 的
**焦点概括** —— 机制第一次在真数据上被证明在干活。

## 判据按设计稿定，材料按判据造

判据写在 [CRITERIA.md](CRITERIA.md)：什么是一个 View、四类差异各自的确切条件、
分类的优先顺序、本层不做什么。两处与设计稿的**有意偏离**都在里面写明了理由。

上游给不出判据需要的形状（Arena 的两方对立是「共享 `to`、不同 `from`」，
而本层要求**同一有序端点对**上互斥）。三条出路的裁决：

```
✗ 改 DCE 的判据去迁就上游    —— 判据该由设计稿决定，不该由上游的写法决定
✗ 在 adapter 里 reify 虚构端点 —— 那是造出上游没有的结构（§C9 #9 / #1）
✓ 承认对不上，把材料按判据造
```

于是有了 `generators/positions.py`：**三份立场**，词汇表取自真实语料
（rl-scaffold 的 36 个真节点），**结构由本层按判据设计**。
一份是另一份的真子集（→ 精炼），两份在同一有序端点对上说了相反的话（→ 矛盾）、
并在同一判断点上给出互不包含的解释（→ 替代解释），其余互缺（→ 缺失）。

```
共识 7 项、矛盾 1、替代解释 2、精炼 4、缺失 13 —— 四类全部自然产生
不是种在四个专用视图上（那套构造已被上一轮的反例扫描证伪）
```

⚠️ 材料是**造的，不是抽取的**：`source_ref` 一律 `authored://`。
把它当成「论文说了什么」会是伪造引用，有测试钉着。

### ⚠️ 一个设计级的冲突：§十一 与 §七 互相拆台

**只有造出真正的立场材料才会暴露这件事。**

§十一 的焦点聚类用「共享节点」并查集 = **传递闭包**；
而 §七 的前提正是「视图已映射到**共享节点空间**」。于是：

```
三份立场共享 con-0001 / con-0005 / judge-0003
→ 任何分歧都通过共享节点并成一团 → 焦点恒等于 1
```

**让分歧可算的那个前提，同时让焦点失效。**

回看上一轮：真实语料上量出 9 个焦点，我把它当成「焦点机制终于在工作了」——
**那是错的。** 那 9 个是**按体裁切片**（几近不相交）造出来的，是材料形状的产物。
换成真正的立场，它立刻塌回 1。

**推论：`focused` 压缩比在焦点为 1 时是假压缩。**

```
三份立场：输入 37 个单元，flat 1.37、focused 4.62
而 focused = 37 / (共识 7 + 焦点 1) = 4.62
        —— 那个数只说明「全都是一团」，不是概括出了结构
```

所以 §十三 两个指标现在的处境是：**Coverage 恒等于 1**（600 个配置零反例），
而 **Compression 只在焦点数不退化时才有意义，可焦点数在预期用法下就是 1**。

### 半径：显式参数，**上界由结构算出来**

`§T0.3` 禁的是「**断言**一个没有基线数据的具体阈值」，**不是禁「有一个显式参数」**：

```
✗ 拍一个半径，当成正确值用                              → 违规
✓ 半径是显式参数，整条曲线报出来，
  且它的上界由结构算出（analysis/focus.py 的 calibrate）  → 不违规
```

```
radius = 0   共享节点（传递闭包）
radius = k   两个分歧的锚点在**结构图**上的距离 ≤ k 就并簇
r*           **焦点塌成 1 的最小半径** —— 超过它焦点不携带信息
可用区间      [0, r*−1]；r* 由结构算出，数据一多自动重算 ← **那就是校准**
```

`foci(divergence, radius=0, views=…)` 默认 0（不改变既有行为）；
`calibrate()` 报整条曲线；`synthesis.provenance.focus_radius` 记下用了哪个值 ——
**换了值，产物就应当看得出换了值**。

### ⚠️ 但半径**不能**解开上面那个冲突，而且这件事被量出来了

`checks/radius.py` 扫了三种材料，**两个现成的恰好落在两个相反的退化极端**：

| 材料 | 曲线（radius → 焦点数） | 判定 |
|---|---|---|
| 立场材料（共享节点空间） | `(0,1)(1,1)(2,1)(3,1)` | **r\*=0** —— radius 0 已经全并成一团（**并得太早**） |
| 真实语料（按体裁切） | `(0,9)(1,9)…(7,9)` | **永不塌** —— 并集图是碎的，半径跨不过分量（**永远并不上**） |
| 中间地带（链，两簇锚点节点不相交） | `(0,2)…(4,2)(5,1)…` | **r\*=5** —— 有可用区间 `[0,4]` |

前两条「半径没用」有**两种完全不同的原因**，而**都不是实现 bug**。
所以第三条是必须的：没有它，「半径机制是死的」与「这两个语料恰好在极端」
在报告上长得一样。

**结论**：半径只在**中间地带**有用（并集图连通 **且** 分歧稀疏到 radius 0 还给出 >1 个焦点）。
而**真正的多视图材料（共享节点空间）落在第一个极端** —— 所以半径**解不开**
§十一 与 §七 的冲突，它只是让「解不开」从一句论断变成了一个量出来的结论。

⚠️ 顺带抓出一个真 bug：第一版算的是「两边的**半径球**相交」，
而两个半径 k 的球相交等价于 `dist ≤ 2k` —— **生效阈值是半径的两倍**。
它不报错，只让曲线在比预期早一半的地方塌下去。抓出它的是那条中间地带用例
（锚点距离 5，曲线却在 3 就并上）。现在 `r*` 精确等于锚点距离，
有测试钉着（`test_radius_semantics_is_exact_distance`）。

**这仍然需要设计稿裁决**：要么接受焦点在共享节点空间下不成立，
要么换一个聚类依据（而不是给现有依据加半径）。

### ✅ 已解开：换的是**依据**，不是尺度

**焦点原先是「划分」，而那个前提从没被论证过** —— 它是实现选择，不是需求。
要求重新写成六条（覆盖 / 压缩 / 非退化 / 可追溯 / 无阈值 / 确定性，
**「是划分」不在其中**），依据也从「结构邻近性」换成**记录的主语**：

```
立场材料上的焦点数：
  距离 ≤ r 的并查集 (r=0..5)      1, 1, 1, 1, 1, 1      ← 退化
  kNN 图弱连通分量 (k=1,2,3,5,8)   1, 1, 1, 1, 1         ← 退化
  按主语分组                      6（视图族 3）          ← 非退化
```

前两种退化的原因同一条：**结构邻近性在共享节点空间上是传递闭包**，
而「多个立场就同一议题争执」的定义**就是**共享空间 ——
**越是对同一件事有分歧，越会并成一团。**

按主语分组给出的话头，每条都是一句话：

```
立场材料   哪个位置上出现竞争解释  judge-0003/explains     2 条
          谁的粒度比谁粗        P1 → P3                   4 条
          哪个视图缺了东西       P1 / P2 / P3          3 / 7 / 3 条
          哪个结构位置被争       case-0001 → con-0001       1 条
真实语料   192 条 omission → 4 个焦点（48×）：其他 63 / 官方文档 61 / 教材 54 / 论文 14
```

**「划分」这个前提实测就是错的**：两族焦点的关联表是**棋盘状而非分块对角** ——
立场材料 **20/20**、真实语料 **192/192** 条记录都牵涉多个视图。

⚠️ **局限要说清**：**焦点是个「话头」，不是「故事」。**
「SC-其他 缺了 63 样东西」回答了「哪儿缺」，没回答「缺的是什么」。
第二级概括（按单元种类、或按「谁还有它」）是下一步，仍然不需要阈值。

⚠️ 另有两条断言原先把「旧依据失效」与「产品失效」**绑成了一个事实**，
换依据后它们红了 —— **而红得对：产品不再失效了。**
现在它们只针对邻近性那一族函数，于是两件事各自被钉住。
**一条断言把两件事绑在一起，就会在修好其中一件时以「失败」的形式报告成功。**

### 二级：形式概念分析（FCA），**只在桶大的时候才用**

一级按主语概括之后，还剩一个明确的局限：
「SC-其他 缺了 63 样东西」回答了**哪儿缺**，没回答**缺的是什么**。
要往下一级就得**同时**看几个特征 —— 而那是 FCA 的本行。

⚠️ **全格不能当焦点集**：立场材料上 20 条记录 → **62 个概念**，
比记录还多。它把记录**展开**了，违反 R2（焦点数须远少于记录数）。
所以两级的正确分工是：

```
一级  按主语分组                      20 → 6     概括
二级  一级焦点**内部**建格，取非冗余概念   7 → 3     展开一层
```

```
立场材料   20 条 → 一级 6（3.3x）→ 一+二级 22（0.9x）   ← 展开，别显示
真实语料  192 条 → 一级 4（ 48x）→ 一+二级 25（7.7x）   ← 概括
```

**二级不是「总是更好」** —— 一个把 20 条变成 22 条的「概括」是反的。
显示规则是**结构性的**：`二级概念数 < 桶内记录数` 才显示。**没有阈值。**
`Sep = 0` 也同理 —— 它意味着这个概念在直接子概念面前完全冗余，是结构事实。

二级在真实语料上露出来的是**成对重叠**：

```
Sep=26  单元:node、类型:omission ｜ 视图 SC-其他/SC-论文   → 那 63 样里 26 个 SC-论文 也缺
Sep=24  关系:dce_untyped、单元:edge ｜ SC-其他/SC-论文      → 还有 24 条边也是两边都缺
```

也就是说那四个体裁切面彼此**嵌套/冗余**，不是独立的 —— 一级看不到这件事。

⚠️ `Sep` 用**两条独立路径**交叉核对（62 个概念逐位相等）。
本仓库吃过「判据写两遍会漂」的亏，所以正确做法不是只写一遍，
而是**写两遍、但必须是两条独立的路、并逐位对账**。

### `stability`：与 `Sep` 同一个来源，**不是同一个量**

```
Sep        比直接子概念多覆盖了什么          —— 新增信息
stability  随机删掉一部分外延后内涵还保得住吗  —— 对噪声的稳健性
σ(C) = |{ A ⊆ Ext(C) | A' = Int(C) }| / 2^{|Ext(C)|}
```

⚠️ 直接枚举 `Ext(C)` 的子集是指数的，但**容斥**恰好把复杂度反过来：
`A' ≠ Int ⟺ A' ⊋ Int ⟺ ∃m ∉ Int` 使 A 里每个对象都有 m。于是
**内涵越大 → 外侧属性越少 → 容斥项越少**，而且 `2^n` 是 2 的幂，
所以**全程精确有理数**（62 个概念 0.15s）。容斥是我推的，
拿**字面定义暴力枚举**在 57 个概念上核过，**精确相同**。

两者差异可量化：**1891 个可比配对里 228 对序相反**。所以两个都要报。

### 「该到第几级」：判据**改过两次**

```
第一版  只用「|Ext| > 1」      → 层 0–4 也算，而那里 Sep>0 的是 0 个
第二版  只用「Sep > 0」        → 层 8 也算，而它只有 1 个概念、外延 1 条
现在    两者都要 + 概念数 < 记录数 → 有用层 [5, 6, 7]（格最深 16）
```

**两次的形状一样：少一个合取项，就把退化情形放进来了。**

顺带回答了一个**反直觉的现象**：**有用的概念集中在深（具体）层，不是浅（一般）层。**
浅层概念多、外延长，读起来像"总览"，但它们在子概念面前**不拥有任何记录** ——
信息完全被更具体的概念覆盖了。

## 跨领域借用：两条已落地

调研与「读过正文 / 只有检索片段」的分栏在 [PRIOR-ART.md](PRIOR-ART.md)。
已落地的两条各自带回一个新结论：

### 一、生态学的 β 多样性：四类互斥标签 → **两个分量 + 方向**

`analysis/beta.py`（出处是 `betapart` 的 CRAN 参考手册，维护者即 Baselga 本人）。
它解开的正是本仓库量出的那条判据层毛病（四类边界随构造移动）：

```
P1 × P2   总 0.3636 = 周转 0.3636 + 嵌套 0.0000   →  纯周转
P1 × P3   总 0.1538 = 周转 0.0000 + 嵌套 0.1538   →  纯嵌套（P1 ⊂ P3）
P2 × P3   总 0.4615 = 周转 0.3636 + 嵌套 0.0979   →  混合
```

**那个歧义消失了** —— 不需要把一个单元塞进四个互斥标签之一。
**refinement 与 omission 不是两类，是同一个嵌套现象的两个方向。**

一条**穷尽验证**的定理（9261 组、`Fraction` 精确算术、**无容差**）：
`β_嵌套 = 0 ⟺ b = c 或 (a = 0 且 min(b,c) > 0)`。
⚠️ 右半边我写错过一次：漏了**空视图**那个退化情形（那时 β_嵌套 = 1 是对的，
空集是任何集合的子集）。**错的是定理陈述，不是代码** ——
而这个形状与本仓库先前栽过的那次一模一样。

### 二、粗糙集：`γ` 成了「DCE 是否只是 graph frequency bookkeeping」的定量答案

`metrics/approximation.py`（Pawlak 1982；出处是 `RoughSets` 的 CRAN 参考手册）。
映射：对象 = 结构单元，条件属性 = 视图，决策属性 = 差异类型，于是
**不可分辨类 = 出现在完全相同的那几个视图里的单元**。

```
正域 = 全体 ⟺ 每个签名类落在单个决策类里 ⟺ 类型是签名的函数
所以  γ = 1 ⟺ 类型判定完全由「出现在哪几个视图」决定
           ⟺ 类型没有携带成员关系之外的任何信息
```

```
合成语料，无植入或只植入缺失    γ = 1.000   ← 就是频率记账，一点没多
合成语料，植入矛盾              γ ≈ 0.88–0.90
合成语料，四类齐植              γ ≈ 0.76–0.90
**立场材料**                   **γ = 0.211**  ← 19 个单元里只有 4 个的签名足以定类型
```

理由直白：一个单元是不是「缺失」，看签名就够了；
而「矛盾」依赖 `(from,to)` 配对与关系种类，**那不在签名里**。

⚠️ **这条发现第一版说得太强，被自己的检查证伪了**：写「只植入缺失 ⟹ γ = 1」，
而某个配置下 γ = 0.8824 —— 私有边让一个 refinement 对**意外出现**了。
正确的陈述是**有条件的**：`类型集 ⊆ {共识,缺失} 且无精炼对 ⟹ γ = 1`。

⚠️ 核正文时还改掉一处公式错误：我原先把 `γ = |下近似|/|X|` 当依赖度，
那是把**近似精度 α = 下/上**的形状挂了 γ 的名字。两个量含义不同，**都算都报**。

**α 与 γ 都不是「多少人说」**，所以都不撞 `§C9 #5` —— 它们量的是**结构**。

## 三条边界（写死，不是风格偏好）

### 一、MVP 不解决 semantic alignment

输入视图**已经映射到 Scaffold 的统一节点空间**。DCE 不判断
「苹果」和「苹果公司」是不是同一个概念 —— 那是 alignment layer 的事。
节点身份 = id 的字面值，**不做任何同名归并**。

### 二、`support` 是描述性事实，不是排序键

设计稿 §八 给的 `support = 出现该节点的视图数 / 总数`（例 `0.8`），
而 arena `§C9` 不变量 #5 是 `Popularity = Evidence`，`§C7.1 ①` 明确把
「投票数 / 热度 / 参与量 / 曝光量」列为**禁止**信号，并给出推荐定义：

> 上层信号**不是「多少人说」，而是「是否在所有观点群里都成立」**……
> 它在结构上不可能违反 #5，**不需要靠人工检查去守**。

所以本仓库：

- **共识 = 合取**（`support == (n, n)`），**没有阈值**，没有「相关视图」这层过滤
- `support` 返回**元组不是比例**（比例会被顺手拿去过阈值或排序）
- 清单**按 key 排，绝不按 support 排**（这条有可执行检查）

### 三、边身份是三元组

`edge_identity = (from, to, relation)`。`A supports B` 与 `B supports A`
**不是同一个结构**（设计稿 §九）。

⚠️ **一个真实的接口缺口**：Scaffold 的 `relations` 是 `list[str]`、**不带种类**；
带种类的边**只有 Arena 有**（`relation.kind` = `§C3.2` 六种 ∪ `§C4` 四种）。
所以词表必须由 adapter **声明**，不能指望 Scaffold 给 —— 本仓库的词表是从
arena 抄的，互斥集 `supports ⊥ contradicts ⊥ qualifies` 也是（依据 `§C4`
把这三者放在同一对端点上的同一个单元格里），并用自检钉住。

## 它做不到什么（如实标记）

| 项 | 状态 |
|---|---|
| 真实 LLM 视图 | **没接**。MVP 只用合成 ground truth（§十四 的要求） |
| 真实数据接入 | **只到 adapter 为止**。`adapters/scaffold.py` 与 `adapters/arena.py` 是**翻译函数**，输入是**最小声明形状**（不是 live DB、不是 arena 的 SQLite）。用真实数据跑通需要有人提供符合那份最小形状的导出 |
| Nested 的映射 | **没做**。nested 是**派生层**（pointer / provenance），而 DCE 的 provenance 是它自己的输出 —— 两者是同一层的位置，不是输入输出关系。本仓库只借了它的**做法**（字段白名单、`「没有」与「有但坏」是两件事`、永不改入参），没有也不需要一个 nested adapter |
| semantic alignment | **不做**，见上 |
| embedding 相似度 | **没做**。用的是字符二元组 Dice 替代品，标得很清楚 |
| 稀疏/长尾规模 | **没测**。反例扫描是 720 个配置、每个几十到几百个单元（整套 6 秒）。真实规模下 `flat` 口径的缺失记录会先出问题 —— 那是 O(视图 × 单元) |
| 真实拓扑 | **用简化代替**。`topology.py` 的四种骨架（随机 / 森林 / 链 / 星）是 Scaffold 与 arena 真实结构的**简化**，不是真形状 |
| Arena 的两方对立 | **判据够不着**，已量出：报出矛盾 0 条。见上面「一处真实的接口错位」 |
| `support` 之外的共识机制 | `§C7.1` 的「跨群共识」在 MVP 规模下**全程休眠**（没有观点群）。本仓库的合取是它在无群情形下的退化形式 |
